# Agency → client account models: GoHighLevel, Zoho Social (Agency), AiSensy, Interakt

Research date: 2026-10-09. Sources are official docs where noted. Third-party sources are labelled "(third-party)". Anything not found in public sources is listed under Gaps. Podo Social mapping context: agency = Organization, client = SocialCustomer.

## GoHighLevel: agency account vs sub-account (location), data, roles, snapshots, SaaS mode/rebilling, client access, API v2 auth

### Takeaway
GoHighLevel has a strict two-level tenancy: one **Agency (Company)** that owns many **sub-accounts (Locations)**. Almost all operational data (contacts, conversations, appointments, social planner, phone numbers, integrations) is location-scoped. People are either **Agency**-type users (scope = the whole agency) or **Account**-type users (scope = sub-accounts explicitly assigned to them). Each user is then an Admin or a User within that scope and gets module and granular permissions. The API mirrors this exactly: OAuth tokens are either `userType: "Company"` (agency) or `userType: "Location"` (sub-account), and an agency token can be exchanged for a location token per `locationId`. Snapshots clone a location's configuration (workflows, funnels, calendars, fields, and so on) but never its records or credentials. SaaS mode lets the agency sell plans that auto-create sub-accounts and rebill usage at a markup through the agency's own Stripe.

### Cited Findings
**Hierarchy and switching**
- There are "two levels to any account: the agency level and subaccounts (referred to as location accounts)". You switch into a client by selecting it from a drop-down at the top of the page. (third-party) — [SupplyGem](https://supplygem.com/gohighlevel-agency-sub-account/)
- You return to the agency level with "Switch to Agency View" in the account switcher. Agency users can schedule automated email performance reports (daily/weekly/monthly) to sub-account admins and users. Agency View scheduling controls need the $497/month plan or higher. Sub-account users without Agency View can still set up schedules inside their own sub-account. — [HighLevel Help: Report Scheduler](https://help.gohighlevel.com/support/solutions/articles/48001236324-setting-up-automated-email-reports-for-sub-accounts-with-the-report-scheduler)
- The agency dashboard shows cross-account roll-up and agency billing metrics (client roster, MRR). Sub-account dashboards show only that client's data. One guide warns that a client given a login could see agency billing data if the agency-level dashboard is the default. (third-party, unverified against official docs) — [automatethejourney.com](https://automatethejourney.com/blog/gohighlevel-dashboards-setup-guide); [ghlexperts.com](https://ghlexperts.com/features/ghl-dashboard)

**User types, roles, permissions (official)**
- User types: **Agency**, "for users who require agency-level access", and **Account**, "for users who should access only selected sub-accounts". Roles: **Admin** "provides administrative capabilities within the user's applicable access scope". **User** "provides access according to the permissions configured for that user". For Account users, "the user can access only the sub-accounts assigned to them". — [HighLevel Help: Manage Agency User Roles and Permissions](https://help.gohighlevel.com/support/solutions/articles/155000002543-manage-agency-user-roles-and-permissions-in-highlevel)
- Permissions are layered. Module permissions mean "if a module is disabled, the user cannot access functionality contained within that module". Granular permissions control "individual supported actions within an enabled module". — same source
- Agency-level permissions include a Sub-Accounts module with separate "Create Sub-Accounts" and "Delete" toggles. Sub-account transfers default to the Agency Owner, who can delegate them to specific Agency Admins. "Login As" (impersonation) is "Default: Enabled" and can be disabled per admin. Affiliate payouts are on for Agency Admins, and Agency Users "cannot process affiliate payouts". There are also sub-account settings (list, Manage Client basic details, Sub-Account Billing, Company Settings). — same source
- Agency Admin actions on shared permissions (user management, reporting, media library) "apply across all sub-accounts". Agency Admins "cannot customize Sub-Account Admin role permissions directly". Sub-account Admins "always inherit full access within their assigned sub-account". To limit someone, create a User role. Adding clients at agency level "will give them unnecessary visibility across all sub-accounts", so add them as a User inside their sub-account instead. — [HighLevel Help: Admin vs User Roles and Permission Scopes](https://help.gohighlevel.com/support/solutions/articles/48001078296) (as quoted in search results; the page itself was not fetched)
- Granular location controls include an "Only Assigned Data" restriction (contacts, opportunities and appointments assigned to the user only) and copying permissions between users. (third-party) — [consultevo](https://consultevo.com/gohighlevel-admin-user-roles-permissions/); [Assistable docs](https://docs.assistable.ai/platform/sub-account-management)

**Snapshots (cloning a client setup)**
- The official creation guide lists as included: workflows, funnels, calendars, forms, emails, triggers, custom fields, custom values, membership content, services, webinars. **Not included:** contacts, appointments, conversations, reputation data, Stripe connections, integrations. Lead Gen Forms are also excluded. — [HighLevel Help: Creating New Snapshots](https://help.gohighlevel.com/support/solutions/articles/48000982512-creating-new-snapshots)
- Selective asset snapshots let you choose exactly which assets to include, refresh only certain parts, and force-create a snapshot when some assets fail. — [HighLevel Help: Selective Asset Snapshots](https://help.gohighlevel.com/support/solutions/articles/155000005146-snapshot-management-selective-asset-snapshots-and-force-snapshot-creation)
- "Assets Protected" (formerly "IP Protected") snapshots stop loaded assets from being re-shared or duplicated. Protected assets show as "Restricted (Assets Protected)" and are left out of new snapshots. — [HighLevel Help: Assets Protected Snapshots](https://help.gohighlevel.com/support/solutions/articles/155000002852-assets-protected-snapshots-called-ip-protected-earlier-)
- Each sub-account keeps a Snapshot Load History of which assets each load contained. This is separate from the Snapshot Asset Viewer. — [HighLevel Help: Snapshot Load History](https://help.gohighlevel.com/support/solutions/articles/155000008264-how-to-view-snapshot-load-history-in-a-subaccount)
- Further exclusions reported by agencies: phone numbers and A2P registration, users/team members, connected social accounts, third-party API keys, media files, billing/rebill settings. Only custom value *keys* carry over, not values. Sources disagree on dashboards and custom reports. (third-party) — [brandblast.com](https://www.brandblast.com/blog/ghl-snapshot); [ghlscaleup.com](https://www.ghlscaleup.com/blog/how-to-create-gohighlevel-snapshot); [consultevo ad manager](https://consultevo.com/gohighlevel-ad-manager-snapshots/)

**SaaS mode / rebilling / white-label (mostly third-party)**
- Rebilling with agency markup is limited to the $497/month Agency Pro plan (SaaS Mode). The $297 Unlimited plan can rebill phone/email at cost only. (third-party, citing the help center) — [setsmart.io](https://setsmart.io/blog/gohighlevel-white-label)
- In SaaS mode the agency defines plans in SaaS Configurator > Plans, with feature toggles and limits per tier, and connects its own Stripe. A client buys a plan, "gets a sub-account and a user created automatically, and is locked out if a payment fails". Usage (SMS, email, AI) is rebilled to that sub-account at the agency's markup. The agency rebilling dashboard shows Total Cost, Total Revenue, Profit/Margin and Active Sub-Accounts. (third-party) — [brandblast SaaS mode](https://www.brandblast.com/blog/gohighlevel-saas-mode); [consultevo rebilling dashboard](https://consultevo.com/gohighlevel-agency-rebilling-dashboard/); [omnionlinestrategies](https://omnionlinestrategies.com/blog/how-to-set-up-gohighlevel-saas-mode-agency-pricing)

**Client-facing access**
- Clients normally get a login as a User in their own sub-account (see roles above).
- Social Planner has an **External Approval Flow**: "share posts with clients and stakeholders using secure magic links". No login is required. Approvers can approve or reject with notes, reschedule, and use bulk actions, and changes sync back. One link can cover one or many posts and can be sent by email, WhatsApp or Slack. — [HighLevel changelog: Social Planner magic links](https://ideas.gohighlevel.com/changelog/social-planner-share-approve-posts-via-magic-links)
- The internal Social Planner approval flow assigns a sub-account user as approver. (third-party) — [consultevo approval guide](https://consultevo.com/gohighlevel-social-post-approval-guide/)

**API v2 auth model (official)**
- OAuth tokens have `userType` either `"Company"` (agency-level APIs, such as Create Sub-Account) or `"Location"` (sub-account APIs, such as Create Contact; the response includes `locationId`). — [HighLevel Marketplace: OAuth 2.0](https://marketplace.gohighlevel.com/docs/Authorization/OAuth2.0)
- To get a sub-account token from an agency token, call `POST https://services.leadconnectorhq.com/oauth/locationToken` with the agency Bearer token, header `Version: 2021-07-28`, and body `companyId` + `locationId`. — same source
- Token exchange and refresh use `https://services.leadconnectorhq.com/oauth/token`. Access tokens last about 24h (`expires_in` 86399 for agency, 86400 for location). Refresh tokens are "valid for up to one year, or until it is used", and are single-use and rotating. — same source
- App settings: Private or Public app; Target User "Sub-account" (recommended for about 95% of apps); Who can install "Both Agency & Sub-account" (Agency-only is an option for white-label SaaS features); Listing type "White-label recommended for marketing agencies". The `INSTALL` webhook is subscribed by default. Scopes include `businesses.readonly/write`, `companies.readonly`, `calendars.*`. — same source
- Private Integration Tokens (API v2) exist for both agencies and sub-accounts and are scoped at creation. Recommended rotation is every 90 days, with a 7-day overlap for the old token (or immediate expiry if compromised). Header: `Authorization: Bearer <token>` + `Version: 2021-07-28`. Legacy API Keys are v1.0, which "has reached end-of-life and is no longer maintained", and gave unrestricted account access. — [HighLevel Marketplace: Private Integrations Token](https://marketplace.gohighlevel.com/docs/Authorization/PrivateIntegrationsToken)

### Inferences
- GHL's model maps closely to Organization (Company) → SocialCustomer (Location). Every client-scoped table is keyed by `locationId`, and agency staff reach a client either through agency-wide rights or through explicit sub-account assignment. For Podo Social this implies a `user ↔ social_customer` assignment table plus an org-level "all clients" flag, instead of per-client roles only.
- The "Login As" default, the warning against adding clients at agency level, and the "Agency Admin can't restrict Sub-Account Admin" rule show the main risk: clients must be scoped to one client tenant, never given org-level membership.
- Magic-link approval without login is a public pattern from a market leader, which supports building tokenised approval links before a full client portal.
- Snapshots split "configuration" (templates, workflows, fields) from "records + credentials" (contacts, social connections, phone numbers). A Podo "client template" feature should copy settings, content templates and approval rules, but never connected social accounts or tokens.

### Gaps
- No official HighLevel article found describing a single combined all-sub-accounts operational view (for example a unified inbox or calendar across clients). Agency dashboard roll-up claims are third-party only.
- Official SaaS-mode and rebilling help articles were not retrieved. Plan prices ($297/$497) and the markup rules come from third parties citing the help center. Current 2026 plan names and prices are not verified.
- White-label mobile app and desktop app specifics were not researched in depth (time limits).
- Exact list of OAuth scopes for social planner endpoints not captured. See `/docs/Authorization/Scopes`.

## Zoho Social (Agency / Agency Plus): brands, client portal, approvals, roles, branded reports, pricing

### Takeaway
Zoho Social organises everything by **Brand** (one brand = one client). Non-agency plans allow 1 brand (Professional can add up to 5 more). **Agency** includes 10 clients and **Agency Plus** 20, with 5-client add-ons and 5 team members. Agency tiers add a **client portal**: clients are invited free as "Client Members" per brand, see an agency-branded dashboard (logo, favicon, custom domain) with only their brand, and can join discussions and approvals. Roles are per brand (Brand Admin, User, Limited Publisher, plus custom roles), with a Portal Owner/Admin above. Agency reports can be scheduled, emailed and agency-branded. Public INR pricing could not be retrieved.

### Cited Findings
- Plan matrix: Free, Standard, Professional and Premium each have 1 Brand (Professional allows a brand add-on up to 5 more). **Agency: 10 Clients** (add-on: 5 Clients), 15–16 channels per client (150–160 total), 5 team members (add-ons available). **Agency Plus: 20 Clients** (add-on: 5), 300–320 channels total, 5 team members. Prices did not render on the fetched page, which says pricing varies by region. The Agency Pricing Calculator mentions "up to 13 channels per client", which conflicts with the 15–16 in the plan tables. — [Zoho Social pricing](https://www.zoho.com/social/pricing.html)
- Agency and Agency Plus client features: "Client invite, portal customization, custom view for clients, free login for clients". Agency reports: "scheduling/emailing reports and agency-branded reports". "Content approvals & workflow" is a Premium feature that Agency tiers inherit. White-label and custom domain are not listed on the pricing page. — [Zoho Social pricing](https://www.zoho.com/social/pricing.html)
- Client portal: invite via **Settings > Brand Members > Client Members** (enter email, Invite). The agency's main dashboard "contains other businesses' data as well", so the portal gives clients a "bird's-eye view of what's happening with their social accounts" and lets them take part in discussions and approvals "to have more control over what goes live". Agency logo and favicon appear in client dashboards and in scheduled or shared custom reports. Domain is default `yourcompanyname.social-public.com` or a custom domain (for example social.zylker.com) set in Portal Settings, which Zoho verifies in "5-6 business days". Available on Agency/Agency Plus. Post undated; images suggest about June 2024. — [Zoho community: Customize your portal for your clients](https://help.zoho.com/portal/en-gb/community/topic/social-media-simplified-with-zoho-social-customize-your-portal-for-your-clients?page=2)
- Default brand roles: **Brand Admin, User, Limited Publisher**. Roles are "sets of responsibilities specific to a job position". — [Zoho Social help: Brand roles](https://www.zoho.eu/social/help/brand-roles.html)
- Permissions by role (Zoho community post): Portal Admin and Brand Admin get publishing, messages, comment/reply, advanced reports, leads data, Zia and inbox. User gets the same minus inbox. Limited Publisher gets messages, comment/reply, advanced reports and Zia, "cannot publish directly and has to submit the posts for approval". Portal Admins, Brand Admins and Users can be approvers. **Clients can be invited and added as approvers.** Custom roles with Publishing can be given approve permission. Portal Admin can assign permissions per channel. The account creator is Portal Owner, and ownership is transferable. — [Zoho community: The need for a social media approval process](https://help.zoho.com/portal/en/community/topic/social-media-simplified-with-zoho-social-the-need-for-a-social-media-approval-process)
- (Competitor-authored) Agency plan listed at **$320/month** (10 brands, 5 members) and Premium at $65 (1 brand). A client "has to be invited and log in to review a post", meaning no login-free approval link is mentioned. — [Cloud Campaign vs Zoho Social](https://www.cloudcampaign.com/lp/vs-zoho-social) (undated, competitor); [RecurPost Zoho alternatives](https://recurpost.com/zoho-social-alternatives/) (Aug 2026, competitor)

### Inferences
- Zoho's model is Portal (agency) → Brand (client), with team members assigned per brand and roles applied per brand. This is close to Podo's Organization → SocialCustomer with per-customer membership.
- Making client logins free and unlimited, while team seats are capped at 5 and charged as add-ons, is a pricing lever: clients are not counted as seats.
- The approval model is role-based (Limited Publisher must submit, client is an approver) instead of link-based. Per competitor claims, clients must log in.

### Gaps
- Current India (INR) pricing for Agency and Agency Plus: the India pricing URL returned 404 and the global page rendered no prices. The $320 figure is competitor-reported and USD.
- No official confirmation of a combined all-brands view (for example a cross-brand calendar or inbox). The help article on the agency dashboard was not retrievable (404).
- Whether the client portal custom domain and branding are included in Agency or only Agency Plus is not stated explicitly.
- Zoho Social public API / partner API for agencies: not researched or found.

## AiSensy: how partners/agencies manage multiple client WhatsApp numbers, onboarding, per-client billing

### Takeaway
AiSensy runs a tiered partner program: Affiliate (20% recurring), Prime Plus, White-label, Direct API and Integration. Multi-client management lives in a separate **Partner Dashboard** (partner.aisensy.com). There the partner creates each client as a "Business", which automatically gets a default "Project" (one project roughly equals one workspace/WABA). The partner sets each client's subscription price and markup on WhatsApp conversation charges and manages credits and billing. White-label partners get their own domain, logo and colour scheme and an embedded signup flow without AiSensy branding. AiSensy handles KYC, setup and go-live.

### Cited Findings
- Partner tiers on the official page: Affiliate ("20% commission on every purchase for as long as they stay"), Prime Plus (commissions also on "Ad Credits and WhatsApp Conversation Credits"), White-Labelled WhatsApp Solution, Direct APIs Partnership ("months" of build effort), Integration Partnership. Self-reported stats: 6000+ partners, 210,000+ businesses. The page is internally inconsistent: min payout ₹999 vs ₹1999, payouts quarterly vs monthly. — [AiSensy Partner page](https://aisensy.com/partner)
- White-label: "Get AiSensy platform under your brand name – custom domain, logo, pricing, everything". AiSensy runs the backend and the partner owns the customer experience. Partners get a Meta Partner Directory listing and an embedded signup flow without AiSensy branding. AiSensy provides "KYC, setup, integrations and go-live support". It claims 300+ white-label partners and 28,000+ WABAs live. — [AiSensy blog: How to Become a WhatsApp API Whitelabel Partner](https://m.aisensy.com/blog/whatsapp-api-whitelabelled-partnership/) (published 29 June 2026)
- White-label billing model: "AiSensy charges you a base price" and partners "Set your own margins on subscription plans" plus markup on WhatsApp conversation charges. "Manage all client pricing from a single Partner Dashboard", with "Full visibility into each client's account". There is a 7-day free trial per new client. Onboarding works "through KYC without needing Facebook Business Manager verification". Setup takes "2–5 days" in the FAQ but "less than 3 days" elsewhere on the same page. No partner fee figures are published. — same source
- Partner Dashboard "helps you manage customers, WABA details, billing, credits, and custom margins". — [AiSensy blog: Partnership Programs](https://m.aisensy.com/blog/aisensy-partnership-programs/) (as quoted in search results)
- Client creation flow in the partner portal: go to `https://www.partner.aisensy.com/` > **Businesses** > create a business. "Once the business is created, the default project gets created". The project name "will be visible in the UI of the Whitelabel dashboard (Only if WL Partnership)". The phone number entered at creation is a contact number and can differ from the WhatsApp API number. Clients set their password through a no-reply email. — [AiSensy partner support doc: Partner dashboard quick guide](https://partnership-support-doc.helpscoutdocs.com/article/29-partner-dashboard-quick-guide) (from search snippet; direct fetch returned 404 on 2026-10-09, so it may be moved or removed)
- AiSensy markets to agencies the ability to "launch, manage, and optimize WhatsApp campaigns for multiple clients from one powerful platform". — [AiSensy: Marketing agencies](https://aisensy.com/industries/marketing-agencies) (search snippet)

### Inferences
- AiSensy's structure is Partner → Business (client) → Project (WhatsApp workspace/number). The client has its own login, and the partner manages pricing and credits from a separate portal instead of from inside the client workspace. That is a "reseller console + tenant apps" pattern, not a single agency workspace with a client switcher.
- Per-client billing combines a subscription (partner-set price over AiSensy's base) with a conversation-credit markup. For Podo, any WhatsApp add-on likely needs a per-SocialCustomer wallet or credit ledger.

### Gaps
- No public documentation on whether one partner login can operate *inside* client workspaces (impersonation or a switcher), or on any combined all-clients inbox or report.
- Exact embedded-signup mechanics (Meta Tech Provider vs BSP, who owns the WABA, Multi-Partner Solution use) are not publicly documented by AiSensy beyond "embedded signup" and "KYC".
- White-label fees and AiSensy base prices are not published ("Request Callback").
- Partner support docs appear to have moved (404).

## Interakt: partner/white-label model, client number onboarding, per-client billing

### Takeaway
Interakt (a Jio Haptik company, Official Meta partner) offers Referral, White-label (ISV) and API partnerships, and positions partners as Meta **Tech Providers**. Partners onboard client numbers via **Embedded Signup** and can later upgrade to Tech Partner. Each client runs as a separate Interakt account with its own subscription and its own prepaid **wallet** for Meta conversation charges, deducted per account. Public partner docs describe a partner portal for tracking leads and earnings, not a multi-client operational console.

### Cited Findings
- The partner program lists "Referral Partnership", "White Label Partnership" and "API Partnership". Models: Freemium ("Zero Cost to Join"), Premium, ISV ("ISV Whitelabel: Your brand. Your pricing. Your customers."; "ISV APIs: Build on Meta APIs without managing the backend"), and High-Volume Enterprise. A "Unified Partner Portal" lets partners "Track leads, conversions, and earnings in one place". Commissions are recurring and paid monthly, and Launch, Pro and messaging add-ons are commission-eligible. No sub-accounts are mentioned. — [Interakt Partner Program](https://interakt.shop/partner-program)
- Tech Provider Program: partners act as WhatsApp service providers while Interakt "manages all the WhatsApp Business platform aspects". Tech Providers "can onboard clients through embedded signup and call Meta's API". Tech Providers "do not have the right to resell their WhatsApp Business Solution usage by extending a line of credit to businesses or charging any markup on conversation fees". The page's FAQ contradicts this by saying partners can "resell... or charge markups". Tech Providers "can upgrade to Tech Partners after demonstrating consistent performance". The white-label feature list includes Embedded Signup, white-labelled support, Platform APIs, **Platform Billing APIs**, and SSO with a customer domain. ISV client steps: apply via Interakt embedded flow, verify Facebook Business Manager to raise limits, update profile, submit templates. — [Interakt blog: Become a WhatsApp Business Partner](https://www.interakt.shop/blog/become-a-whatsapp-business-partner) (published 28 Aug 2024, so older than 2026)
- Wallet: "only applicable for WhatsApp conversations charges and not subscription charges". "The balance will be deducted from the wallet balance for each Interakt account separately". Balances are non-refundable. GST is charged on recharge, not on deduction. — [Interakt: Prepaid wallet FAQs for enterprise customers](https://www.interakt.shop/resource-center/prepaid-wallet-faqs-for-enterprise-customers/) (as quoted in search results)
- Free-tier conversations were historically counted "at a WABA level". — Interakt notice quoted via search (older; Meta moved to per-message pricing in 2025, so this is likely outdated)
- Plan price claims conflict across third parties: "$99/month", "₹999–4,999/month", "₹3,499/quarter or ₹11,999/year". (third-party, unverified) — [zoko.io Interakt pricing guide](https://www.zoko.io/post/interakt-pricing-guide); [hyperleap.ai](https://hyperleap.ai/blog/whatsapp-chatbot-pricing-india-2026)

### Inferences
- Interakt's model is effectively one account per business, with billing (subscription + wallet) per account. An agency managing many clients holds many accounts, and the partner portal is for commercial tracking. White-label partners get Platform and Billing APIs plus SSO to embed this in their own product.
- Meta's rules on markups for Tech Providers vs BSPs constrain who can resell conversation fees. Podo, as a non-BSP, should not plan to mark up Meta charges unless it goes through a BSP partner programme.

### Gaps
- No public documentation of an agency console that switches between client Interakt accounts or shows a combined view.
- Whether several numbers under one Interakt account share a wallet is not documented.
- Current (2026) Interakt plan prices are not confirmed from the official pricing page (not fetched).
- Platform API and Billing API references for partners are not public.

## Cross-product: client switching and combined all-clients views

### Takeaway
All four separate client data hard at the client-tenant level (GHL Location, Zoho Brand, AiSensy Business/Project, Interakt account). Agency staff move between clients with a switcher (GHL drop-down / "Switch to Agency View"; Zoho brand selection) or a separate partner console (AiSensy, Interakt). Publicly documented combined all-clients views are limited to agency-level dashboards and reports: GHL agency dashboard and Report Scheduler, Zoho agency reports, AiSensy partner dashboard for billing and margins. No vendor publicly documents a unified cross-client inbox or calendar.

### Cited Findings
- GHL: drop-down switcher (third-party, [SupplyGem](https://supplygem.com/gohighlevel-agency-sub-account/)); "Switch to Agency View" and agency-level report scheduling ([HighLevel Help](https://help.gohighlevel.com/support/solutions/articles/48001236324-setting-up-automated-email-reports-for-sub-accounts-with-the-report-scheduler)).
- Zoho: the agency dashboard "contains other businesses' data as well", which is why a client portal is needed ([Zoho community](https://help.zoho.com/portal/en-gb/community/topic/social-media-simplified-with-zoho-social-customize-your-portal-for-your-clients?page=2)). Agency-branded scheduled reports are listed on the pricing page ([Zoho pricing](https://www.zoho.com/social/pricing.html)).
- AiSensy: Partner Dashboard gives "Full visibility into each client's account" and one place for client pricing ([AiSensy WL blog](https://m.aisensy.com/blog/whatsapp-api-whitelabelled-partnership/)).
- Interakt: "Unified Partner Portal" for leads, conversions and earnings ([Interakt Partner Program](https://interakt.shop/partner-program)).

### Inferences
- A combined "all clients" calendar, approvals queue or inbox would be a differentiator for Podo, since none of these vendors publicly document one. Unverified: a GHL roll-up view may exist in-product.

### Gaps
- Product UIs were not inspected directly (no accounts). All "combined view" conclusions rest on public documentation only.
- Meta Embedded Signup / Multi-Partner Solution official docs were not fetched in this pass. 360dialog states Tech Providers can manage multiple WABAs via a Multi-Partner Solution ([360dialog docs](https://docs.360dialog.com/partner/get-started/tech-provider-program)), but this is not Interakt- or AiSensy-specific.
